# 异常处理

### 异常 vs 普通条件判断

- **适合 if 分支**：业务规则内的正常分支，如成绩是否及格、菜单选项判断
- **适合异常处理**：运行时的失败情况，如字符串转数字失败、文件不存在、除数为 0、下标越界
- 核心区别：异常不替代条件判断，专门处理正常流程之外的失败场景

| 异常类型              | 触发场景                     |     |
| ----------------- | ------------------------ | --- |
| ValueError        | 类型正确但值不合法，例 `int("abc")` |     |
| TypeError         | 对象类型不匹配，例字符串与数字非法运算      |     |
| ZeroDivisionError | 除数为 0                    |     |
| IndexError        | 序列下标越界                   |     |
| KeyError          | 访问字典不存在的键                |     |
| FileNotFoundError | 打开不存在的文件                 |     |

### 自定义异常

- 定义方式：继承 `Exception` 类，通常仅需定义类名即可
    ```
    class ScoreError(Exception):
        pass
    ```

- 作用：为业务错误提供专属的异常类型，区分语法错误与业务规则错误，便于精准捕获和定位问题

推荐写法：`except Exception as e:`，明确捕获常规异常同时保留错误信息
except (ValueError, ZeroDivisionError) as e:

### finally 子句

- 执行时机：无论是否发生异常，最终一定会执行
- 典型用途：关闭文件、释放资源、恢复现场，保证善后操作一定执行
