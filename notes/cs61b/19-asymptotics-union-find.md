# 增长阶与并查集

## Order of Growth（增长阶）
### **Big-O** 是“==上界==”：

说 `f(N) = O(g(N))`，意思是当 `N` 很大时，`f` 不会比 `g` 长得更快得离谱。你可以把它理解成“最多这么慢”或“不会超过这个量级”。

### Big-Theta** 是“==紧确界==”：

说 `f(N) = Θ(g(N))`，意思是 `f` 既不会比 `g` 快很多，也不会比 `g` 慢很多，二者在增长速度上是同一个量级。你可以把它理解成“就是这个量级”。

## 问题导入：动态连通性（Dynamic Connectivity）

### 初始实现方案：`List<Set<Integer>>`（将一群set联通，使其能够进行内部联合访问）


| 操作                 | 复杂度  | 说明                                                                                                                        |
| ------------------ | ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 构造器                | Θ(N) | 初始化时为每个元素创建单元素集合，时间与元素总数 `N` 成正比                                                                                          |
| `connect(x,y)`     | O(N) | 1. 遍历列表找到 `x` 和 `y` 所在的集合（最坏遍历 `N` 次）<br><br>2. 合并两个集合（拷贝其中一个集合的所有元素，最坏 O (N)）<br><br>注：最坏情况为 Θ(N)，用 O (N) 表示 “运行时间不超过线性” |
| `isConnected(x,y)` | O(N) | 先遍历列表找到 `x` 所在集合（O (N)），再检查 `y` 是否在集合中（HashSet 内为 O (1)），整体为 O (N)                                                        |
==但是==，connect和isConnected方法均为线性，当计算级数大的时候，会超时，而导致其的根本原因为：**每次操作需要遍历 / 拷贝整个集合，没有利用集合的层级关系优化操作**

下面，我们开始优化：

## Quick Find（用整数数组代替list（Set））
| 操作            | 复杂度  | 说明                                          |
| ------------- | ---- | ------------------------------------------- |
| 构造器（初始化）      | Θ(N) | 初始化时，每个元素的`id[i] = i`（自己是自己集合的 id），需要遍历整个数组 |
| `isConnected` | O(1) | 直接比较两个值，一步完成                                |
| `connect`     | O(N) | 每次合并都要遍历整个数组，修改所有和`pid`相同的元素，时间和元素总数`N`成正比  |

欸，我们注意到isConnect时间缩短了（相当于做了个==字典==），但是connect**操作还是需要全扫一遍数组**,这时候，就得请出宗门老祖了————**==树状结构==**

## Quick Union
**整体逻辑结构：**
- `parent[i]`：元素`i`的直接父节点
- 根节点：父节点指向自身 / 标记 - 1，会顺着父节点一路回溯
- 同一棵树 = 同一个连通集合

这个东西优化了合并速度，干成O(1)了，读取速度略慢，最坏变为O(n)的链表，其效率取决于树的高度
