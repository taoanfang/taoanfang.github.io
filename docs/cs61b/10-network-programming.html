CS61B · Java 语言基础

网络编程

TCP/IP、Socket、UDP 与多线程网络通信。

3 分钟 第 10 / 20 篇

1. TCP/IP 四层参考模型

Java 网络编程核心作用于传输层与应用层交界处。

层级（由下至上） 名称 核心功能 代表协议 / 组件
第 1 层 链路层（网络接口层） 处理物理硬件接口，对接传输介质 网卡、设备驱动
第 2 层 网络层（互联层） 数据分组、路由转发，标识网络主机 IP 协议
第 3 层 传输层 控制端到端通信，区分应用程序 TCP、UDP、Socket
第 4 层 应用层 面向应用程序的协议，Java 主要交互层 HTTP、FTP、DNS、SMTP

2. TCP 与 UDP 协议对比

对比维度 TCP UDP
连接特性 面向连接（三次握手建立链路） 面向无连接（直接发包）
可靠性 可靠，保证数据无差错、不丢失 不可靠，尽力传输，不保证送达
资源消耗 高，延迟大 低，延迟小
传输形式 字节流 独立数据报
典型场景 文件传输、邮件发送 直播 / 视频、实时游戏、语音通话、物联网

TCP 三次握手

  1. 客户端 → 服务端：发起连接请求
  2. 服务端 → 客户端：回送响应，确认收到请求
  3. 客户端 → 服务端：再次发送确认，连接正式建立

3. IP 地址与端口号

  • IP 地址：网络中主机的唯一标识，IPv4 为点分十进制格式（如127.0.0.1）

    • 组成：网络地址 + 主机地址
    • 特殊地址：127.0.0.1 为本机回环地址
    • 分类：A/B/C/D/E 五类，局域网常用 C 类（192.0.0.1~223.255.255.254）

  • 端口号：主机内应用服务的唯一标识

    • 范围：0~65535，其中0~1023为系统预留端口
    • 作用：IP 定位主机，端口定位主机内的具体应用

4. 基础工具类

InetAddress（IP 地址封装类）

无公共构造方法，通过静态方法获取实例：

  • getLocalHost()：获取本机 IP 对象
  • getByName(String host)：根据域名 / 主机名获取 IP 对象
  • getHostAddress()：获取字符串格式的 IP 地址
  • getHostName()：获取主机名 / 域名
  • isReachable(int timeout)：检测主机是否可连通

URL（统一资源定位器）

  • 格式：传输协议://主机名:端口号/文件名#引用

  • 核心方法：

    • openStream()：获取网络资源输入流，可读取网页源码
    • openConnection()：获取 URL 连接对象

二、TCP 网络编程

核心类：ServerSocket（服务端）、Socket（通信链路）

1. 核心 API

ServerSocket（服务端监听者）

  • 职责：绑定端口，阻塞等待客户端连接，连接成功返回专属 Socket

  • 常用构造：ServerSocket(int port) 绑定指定端口

  • 核心方法：

    • accept()：阻塞方法，等待客户端连接，连接成功返回 Socket 对象
    • close()：关闭服务端

Socket（双向通信链路）

  • 职责：代表客户端与服务端的通信连接，两端各持有一个 Socket

  • 常用构造：Socket(String host, int port) 客户端发起连接

  • 核心方法：

    • getInputStream()：获取输入流，接收对方数据
    • getOutputStream()：获取输出流，发送数据给对方
    • close()：关闭连接，需先关闭关联的 IO 流

2. 单线程 TCP 通信流程

先启动服务端，再启动客户端

服务端步骤：

  1. 创建ServerSocket，绑定端口
  2. 调用accept()阻塞等待客户端连接
  3. 通过 Socket 获取输出流，发送数据
  4. 关闭流、Socket、ServerSocket

客户端步骤：

  1. 创建Socket，连接服务端 IP + 端口
  2. 通过 Socket 获取输入流，读取数据
  3. 关闭流、Socket

3. 多线程 TCP 通信（并发）

解决单线程无法同时处理多客户端的问题

  • 主线程：while(true)循环调用accept()，持续接收新连接，只做分发
  • 子线程：每接入一个客户端，新建独立线程处理该客户端的所有数据交互
  • 特点：主线程不阻塞，多客户端可并发访问，互不干扰

三、UDP 网络编程

核心类：DatagramSocket（收发端口）、DatagramPacket（数据包）

1. 核心 API

DatagramPacket（数据报包）

  • 作用：封装 UDP 传输的数据，自带寻址信息

  • 接收端构造：DatagramPacket(byte[] buf, int length) 仅准备空缓冲区

  • 发送端构造：DatagramPacket(byte[] buf, int length, InetAddress addr, int port) 需指定目标地址 + 端口

  • 常用方法：

    • getData()：获取数据包内的字节数据
    • getLength()：获取有效数据长度
    • getAddress() / getPort()：获取发送方的 IP / 端口

DatagramSocket（数据报套接字）

  • 作用：负责数据包的发送与接收

  • 构造方法：

    • DatagramSocket()：系统分配随机端口，多用于发送端
    • DatagramSocket(int port)：绑定固定端口，多用于接收端

  • 核心方法：

    • receive(DatagramPacket p)：阻塞方法，等待接收数据包
    • send(DatagramPacket p)：发送数据包
    • setSoTimeout(int timeout)：设置接收超时，避免永久阻塞
    • close()：关闭连接

2. 单线程 UDP 通信流程

必须先启动接收端，否则数据直接丢失

接收端步骤：

  1. 创建DatagramSocket，绑定固定端口
  2. 创建空的DatagramPacket作为缓冲区
  3. 调用receive()阻塞等待数据
  4. 解析数据包，打印内容与发送方信息
  5. 关闭资源

发送端步骤：

  1. 创建DatagramSocket（随机端口）
  2. 封装数据、目标 IP、端口到DatagramPacket
  3. 调用send()发送数据包
  4. 关闭资源

3. 多线程 UDP 通信（简易聊天）

  • 接收线程：循环调用receive()，持续监听并打印收到的消息
  • 发送线程：循环读取控制台输入，封装数据包并发送，支持退出指令
