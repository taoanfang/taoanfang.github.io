9.1 特殊方法与协议

核心思想

  • 特殊方法（双下划线开头结尾）是 Python 的协议机制：实现对应方法后，自定义对象就能像列表、字典等内置类型一样，使用原生语法操作。

  • 常见语法与特殊方法的对应关系：

    • obj[i] → 自动调用 __getitem__
    • obj[i] = x → 自动调用 __setitem__
    • len(obj) → 自动调用 __len__
    • for x in obj → 自动调用 __iter__ + __next__
    • next(it) → 自动调用 __next__

  • 意义：保证对象行为的一致性，让自定义类型无缝融入 Python 的语法体系。

9.2 容器协议与自定义容器

容器是用于保存多个元素的对象大类，序列、字典、集合都属于容器。通过实现容器相关特殊方法，可以自定义具备原生容器行为的对象。

核心容器特殊方法

1. __len__

  • 作用：定义对象的长度计算规则，支持 len(obj) 语法
  • 触发时机：调用 len() 函数时自动执行
  • 适用场景：自定义序列、字典、集合类对象

2. __getitem__

  • 作用：定义下标取值的逻辑，支持 obj[index] 语法
  • 触发时机：使用中括号访问元素时自动执行
  • 扩展能力：不仅可以模仿列表的索引取值，还能自定义专属的取值规则（如按需计算的无穷序列，无需真实存储所有元素）

3. __setitem__

  • 作用：定义下标赋值的逻辑，支持 obj[key] = value 语法
  • 触发时机：使用中括号给元素赋值时自动执行
  • 常与 __getitem__ 配套使用，完整实现类序列 / 类字典的读写能力

4. __delitem__

  • 作用：定义删除元素的逻辑，支持 del obj[key] 语法
  • 触发时机：使用 del 删除指定元素时自动执行
  • 作为容器协议的补充，完善增删改查的完整能力

内建类型子类化

  • 可以直接继承内置类型（如 list、dict）扩展功能，只需重写需要修改的方法，其余行为全部复用父类。
  • 示例：CounterList 继承 list，新增访问计数器，每次下标访问时计数；reverse、append 等方法直接继承自原生列表。

课堂练习：Bag 书包类

  • 需求：内部用列表保存物品，支持 len(bag) 查数量、bag[i] 读元素、bag[i] = x 改元素
  • 实现：分别实现 __len__、__getitem__、__setitem__，内部代理到内置列表的对应操作

9.3 属性与 property

访问器模式

  • 传统封装方式：通过 getter/setter 方法间接访问私有属性，实现数据校验、逻辑控制
  • 缺点：调用必须显式写方法名，不符合属性访问的自然语法

property 属性描述器

核心作用

将属性的读、写、删操作转化为方法调用，对外保持属性访问的简洁写法，对内拥有方法的控制能力，兼顾使用体验与封装性。

两种常用形式

  1. 可读写属性

    • 用 @property 装饰 getter 方法（方法名即为对外的属性名）
    • 用 @属性名.setter 装饰 setter 方法
    • 典型场景：成绩属性，赋值时自动校验 0~100 的合法范围

  2. 只读计算属性

    • 仅实现 getter，不提供 setter
    • 适合根据已有属性动态计算得出的值（如成绩等级、是否及格），外部无法直接修改

课堂练习：Course 课程类

  • 需求：score 属性带 0~100 范围校验，passed 只读属性（分数≥60 返回 True）
  • 实现：score 用 property + setter 做校验，passed 仅用 property 实现动态计算逻辑

9.4 可迭代对象与迭代器

for 循环的底层本质

python

运行

for x in obj:
    print(x)

等价执行流程：

  1. 调用 iter(obj) 获取迭代器 it
  2. 循环调用 next(it) 逐个取值
  3. 捕获 StopIteration 异常时终止循环

两个核心概念

表格

概念 定义 核心方法 特点
可迭代对象 可以被 for 遍历的对象（数据来源） __iter__ 本身不负责逐个取值，只负责提供迭代器
迭代器 负责逐个产出元素的执行对象 __iter__ + __next__ 记录当前位置，逐次前进，用完即耗尽

两个核心特殊方法

  1. __iter__

    • 触发：iter(obj) 时调用
    • 作用：返回一个迭代器对象
    • 迭代器自身的 __iter__ 会返回自身

  2. __next__

    • 触发：next(it) 时调用
    • 作用：返回下一个元素
    • 结束规则：无更多元素时抛出 StopIteration 异常，作为循环结束的信号

关键特性

  • 列表可反复遍历：列表是可迭代对象，每次 iter(列表) 都会生成全新的独立迭代器，互不干扰。
  • 迭代器只能使用一次：迭代器会持续记录当前位置，元素取完后不会自动重置，再次调用 next() 会直接抛出异常。

9.5 生成器

生成器函数

  • 定义：包含 yield 关键字的函数，本质是更简洁的迭代器实现方式

  • 执行特点：

    1. 调用生成器函数不会立即执行函数体，而是返回一个生成器对象
    2. 执行到 yield 时暂停，保留当前所有运行状态，并产出对应的值
    3. 下一次调用 next() 时，从上次暂停的位置继续执行

  • 与普通函数对比：普通函数 return 一次性返回全部结果；生成器 yield 逐个产出结果，适合大数据量、流式处理场景，显著节省内存。

生成器表达式

  • 语法：(表达式 for 变量 in 可迭代对象)，形式与列表推导式类似，使用圆括号
  • 特点：不会一次性生成所有元素，按需计算，内存效率远高于列表推导式

递归生成器与 yield from

  • yield from 子生成器：将子生成器的所有元素逐个向外产出，大幅简化递归生成器的写法
  • 等价于手动遍历子生成器，逐个 yield 元素
  • 典型应用：展开任意深度的嵌套列表 / 元组

典型应用场景

  • 超大数据量序列：避免一次性加载全部内容到内存
  • 流式输出：如大模型对话的逐字返回效果
  • 嵌套结构扁平化：多层嵌套容器的一维展开

课堂练习：gen_even 偶数生成器

  • 需求：依次产生 0, 2, 4 … 共 n 个偶数
  • 实现：循环配合 yield 逐个产出数值

9.6 综合案例

AIMessageLog 消息日志

  • 内部用列表存储消息，实现 __len__、__getitem__、__iter__
  • 对外表现出和列表一致的使用体验，同时封装消息添加等业务方法

LearningSession 学习记录

  • 融合三种能力：

    1. 容器行为：__len__、__getitem__、__iter__ 支持原生遍历与访问
    2. 业务校验：添加成绩时校验分数范围
    3. 计算属性：average_score 用 property 实现，动态计算平均分

迭代器常见 Bug

  • 错误写法：__next__ 只返回值、不更新当前状态 → 永远返回同一个值，造成死循环
  • 修正方式：先保存当前值，更新位置计数器，再返回旧值

本章小结

  1. 特殊方法是 Python 的对象协议，实现对应方法即可让自定义对象无缝支持原生语法
  2. 容器协议通过 __len__、__getitem__、__setitem__、__delitem__ 实现类序列 / 类字典的原生行为
  3. property 将方法包装为属性访问形式，兼顾语法简洁性与数据校验、封装能力
  4. 可迭代对象实现 __iter__ 提供迭代器；迭代器实现 __iter__ + __next__ 逐个产出元素，结束时抛出 StopIteration
  5. 生成器是简化版迭代器，通过 yield 实现暂停 - 继续的执行模式，内存效率高，适合流式、超大数据场景
  6. 面向对象设计的进阶：不止是定义类和方法，更要让对象融入 Python 的语法体系，符合语言原生的使用习惯

  2. 实现 Course 类，带校验的 score 属性与只读的 passed 属性
  3. 实现 gen_even 偶数生成器，分别用 for 和 next () 测试
  4. 排查并修复有死循环问题的自定义迭代器
